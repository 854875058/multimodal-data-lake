# 项目待办清单

最后更新: 2026-05-07

本文档用于统一记录当前项目的功能补齐、页面重做、能力融合和后续优化项。

后续推进规则:

- 每个待办用唯一编号管理，便于后续增删改查。
- 状态只使用: `TODO` / `DOING` / `DONE` / `DROP`
- 新需求先补到本文档，再开始实现。
- 已完成项不删除，改为 `DONE`，保留实现痕迹。
- 明确废弃或不再做的项，改为 `DROP`，并写原因。

## 当前范围

本轮 backlog 主要来自三部分:

1. 当前仓库 `multimodal-data-lake` 已有功能与缺口
2. `多模态数据湖_prd/BONC_Stitch_ProductSpec_V1.md` 中明确提出的重点页面和能力
3. `Tower-Eye` 中可复用的标注、多模态检索、Agent 编排能力

## 融合原则

后续所有改造遵循以下原则:

1. 现有能力优先保留，不做“为了重做页面而删功能”的处理。
2. 原有图谱能力必须保留，后续只允许做融合、重组、增强，不允许用新页面简单替换掉原有图谱能力。
3. 对外表现是“统一产品”，不是“复制一个新系统再把旧功能丢掉”。
4. 新引入的 PRD 设计、Tower-Eye 能力，默认都要先判断如何与当前项目已有能力融合，再决定是否落地。

## 状态说明

- `TODO`: 已确认要做，尚未开始
- `DOING`: 正在开发
- `DONE`: 已完成并通过当前轮验证
- `DROP`: 暂不做或明确废弃
