## 一、项目概述

**Multimodal Data Lake** 是一个面向企业场景的多模态数据湖仓运营平台，统一覆盖数据接入、内容解析、向量化入湖、统一检索、资产治理、工作流编排、MPP/Doris 运维、权限管控与 AI Agent 协作。

**技术栈：**
- 前端：React 18 + Vite 7 + Arco Design + ECharts
- 后端：FastAPI + Pydantic v2 + Uvicorn
- 存储：LanceDB（向量湖）+ SQLite（元数据）+ SeaweedFS/S3（对象存储）+ Doris（联邦查询）
- AI：BGE (bge-small-zh-v1.5) + CLIP (ViT-B-32) + Whisper (base) + DeepSeek
- 计算：Ray 分布式计算框架

**默认账号：** `admin` / `admin123`  
**默认端口：** `27843`

## 八、AI Agent 系统

### 8.1 Agent 架构

系统采用三 Agent 协作架构，由 `AgentCoordinator` 统一调度：

| Agent | 文件 | 功能 |
|-------|------|------|
| **BrainAgent（大脑）** | `brain_agent.py` | 项目规划、任务队列管理、可执行计划生成 |
| **CodeAgent（代码）** | `code_agent.py` | 代码实现、自验证（Python 语法检查） |
| **TestAgent（测试）** | `test_agent.py` | 自动生成验证命令、执行测试、分析失败原因 |
| **AgentCoordinator** | `agent_coordinator.py` | 协调三 Agent，支持 planning_only 和 execution 模式 |

## 九、数据流与处理链路

### 9.1 数据接入流程

```
本地上传/来源接入 → ETL 处理 → 内容提取 → 向量化 → LanceDB 入库
                                      ↓
                              SQLite 元数据注册
                                      ↓
                              SeaweedFS 对象存储
```

### 9.2 检索流程

```
用户查询 → 向量化 (BGE/CLIP) → LanceDB 检索 → 结果排序 → 返回
         → SQL 查询 → Doris 执行 → 结果表格 → 返回
         → 混合检索 → RRF 融合 → 返回
```

### 9.3 工作流执行流程

```
画布编排 → 拓扑排序 → 构建 Ray Job → Ray 执行 → 结果回写
```

## 十、认证与权限

### 10.1 认证状态

| 级别 | 说明 | 涉及接口 |
|------|------|----------|
| 无认证 | 大部分接口直接可访问 | dashboard, search, files, upload, platform, operators, ray, doris, versions |
| 本机限制 | 仅 127.0.0.1 可访问 | agents, system/logs |
| 用户登录 | POST `/api/users/login` 获取 token | 登录接口本身无需认证 |
| 管理员 | admin 角色拥有全部权限 | 用户管理、权限管理页面 |

### 10.2 默认角色

| 角色 | 权限 |
|------|------|
| admin | `["*"]` 全部权限 |
| editor | `["read", "write", "upload"]` |
| viewer | `["read"]` |

### 10.3 安全风险

**当前缺少全局认证中间件**。登录接口存在，RBAC 表已初始化，但未在路由层面强制执行。生产环境需添加 OAuth2/JWT 中间件。
